# 题库填充的批次计划（2026-11-19）

目标：把 205 个（诊断节点 × 能力线）格子补到**最低档**（每格 1 易 1 中 1 难），即每个格子的
四阶段可以被构造出来。稳健档（每格 2/2/2）等最低档完成后另行安排。

这份文件是**唯一**需要人手维护的状态：批次划分。完成度不写在这里，直接跑
`check_ability_coverage.py` 现算——手写的进度会漂，现算的不会。每次开工先跑它，从第一个不满的批接上。

把计划留在对话里等于让它丢。每批 ≤40 题、≤16 格，一批一提交，坏了只回滚一批。

## 每批怎么做

1. `python knowledge-eval/scripts/check_ability_coverage.py --subject X --detail` 看这批缺哪些格子
2. 写 `knowledge-eval/batches/<subject>-<batch>.jsonl`，一行一题（字段见下）
3. `python knowledge-eval/scripts/batch_spec.py --subject X --spec <file>`（先 `--dry-run` 看拒绝行）
4. 四条门禁：`check_schema.py` / `check_content.py` / `check_outline_coverage.py` /
   `check_ability_coverage.py --subject X --detail`
5. 一个 commit

**完成定义（DoD）**：这批格子全部 `floor`；四条门禁全绿；填空题 100% 带验算；一个 commit。

## 规格格式（`batches/*.jsonl`，一行一题）

| 键 | 含义 |
|---|---|
| `n` | 节点，`d06` 或 `math-6up-d06` |
| `a` | 能力线，必须是该节点 `ability_lines` 里的一条 |
| `d` | 易 / 中 / 难 |
| `t` | 选择题 / 填空题 / 判断题 |
| `s` | 题干，≤120 字，**不得与全库任何题干重复** |
| `o` | 选项，`|` 分隔（选择题、判断题） |
| `k` | 选择题填标号；填空题填答案 |
| `x` | 填空题的其他等价写法，`|` 分隔 |
| `e` | 解析 |
| `g` | 标签，`|` 分隔，默认节点名 |
| `c` | **数学验算式**：填空题必须算出答案本身；选择题在有算式时必须为 True |

`c` 是这套流程的核心。一回合写四十道题一定会有算错的地方，`1 / Fraction(3, 7)` 不会。
语文和英语没有对应物：它们只过形式校验，对错要靠读。

语文和英语的解析**不许用 A/B/C/D 指代选项**（“A 是‘想要’”），要引用选项原文。选项重排之后
字母就指错人了，而文件里看不出任何异常。`batch_spec.py` 写库前拒一次，`check_content.py` 再拒一次；
数学豁免——那里的 A/B/C 是图中点的名字，`C` 还是周长符号（`C = 2πr`）。

工具的行为：整批要么全写、要么全不写；同一批重跑会报"already applied"并保持文件不变；
拒绝了会逐行点名，且不能用 `--force` 绕过。

## 失败怎么处理

- **工具拒绝某行** → 改那一行，不绕过。门禁被绕过一次就再不会被信任。
- **门禁不过** → 只回滚这一批（`git checkout knowledge-eval/data/`），一批一提交就是为这个。
- **上下文被压缩** → 读本文件 + 跑 `check_ability_coverage.py`，从第一个不满的批继续。
