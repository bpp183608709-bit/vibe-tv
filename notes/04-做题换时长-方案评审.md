# 04 · 做题换时长：方案评审

> 待确认事项见 `docs/待定事项-做题换时长.md`（60 条，其中 12 条为阻断项）。本文只记架构判断和风险结论，不是规格。

## 一、新方案要解决的问题

原来"每天一个固定总时长"在家里几乎用不起来：工作日孩子只有少量时间，周末却有大把时间，一个数字两边都不合适。

新方案把控制从**配给制**改成**赚取制**：每天有基础额度（如 1 小时），用完以后通过做对一组题换时长，或由家长输密码加时长。

这个方向是对的。但"赚取制"的安全性取决于一件事：**答题结果能不能被伪造**。这是它和配给制最本质的差别——配额是写在本地的数字，赚取的额度则来自一个可能不可信的客户端。

## 二、核心架构判断：加时长不能发生在本地

如果实现成「电视上做题 → 本地判分 → 本地加额度」，等于把印钞机放在孩子房间。电视上的 APK 可以被拆包、被改数据、被改系统时间。

建议的链路：

```
电视请求题组 → 服务端出题（带知识点标签、去重）
  → 孩子作答 → 服务端判分
  → 通过则签发一次性签名凭证（时长 + 有效期 + 设备绑定）
  → 电视离线验签，兑换成当天额度
```

这样做恰好复用现有工程的两个概念：

- `WatchTicket` 从「家长手动发票」扩展成「服务端签票」，形态不用变；
- `Parental.extendDaily()` 写入的 `dailyExtraMs` 本来就是"当天有效、跨天清零"，和凭证语义天然对齐。

**断网时**：已换到的时长照样能用（凭证在手里），没网就换不了新的。这是可接受的失败模式。另需本地常备 2–3 组预取题，避免 API 故障时孩子当天只剩 1 小时——那是灾难级体验，家长会直接关掉功能。

## 三、和现有工程的三个冲突

1. **状态机是三态**（`Normal` / `Interval` / `DailyLimit`），新需求要增加"赚取中"这个态，而且做题界面必须明确不计时。
2. **`dailyMinutes = 0` 现在表示"不限"**，与"基础 1 小时"的语义打架。要定清楚：不限额度时做题面板还出不出现。
3. **`WatchTicket` 是纯内存对象**，重启即失。做成凭证必须落盘 + 防篡改。

另外，`docs/PARENTAL.md` 第 6 阶段已经论证过「手机页不做」，理由是"孩子也能摸到同一台手机，收益不抵风险"。新的公网 H5 家长中心把这个风险放大了，鉴权标准必须比局域网 token 高一个量级：独立账号 + 二次确认 + 设备绑定 + 操作留痕。

## 四、会让方案直接失效的风险

| 风险 | 结论 |
|---|---|
| **无限重试 = 老虎机** | 全对才有效 + 2~4 选项 + 可重来，孩子不需要会做，一直点就行。必须同时上「题目 N 天不重出 / 选项顺序随机 / 失败冷却 / 单日尝试与成功双上限」，缺一不可 |
| **"全对"规则击穿中等生** | 5 题跨学科、每题 80% 正确率时全对率仅 33%；60% 时只剩 7.8%。建议错 1 题给半份 |
| **"没学过"的题必然出现** | 进度一旦不准，孩子必错 → 整组作废 → 死循环。但允许直接跳过又会被全部标成"没学过"。解法是标记后照答、不计失败次数，连续标记触发家长复核 |
| **密码比做题省力** | 只要有一条更省力的路，孩子一定走那条。"做题优先"靠界面排序实现不了，必须限制密码每天加时长的次数 |
| **进度维护会烂尾** | 家长手动设"第几单元"，一周不更新就废。建议按校历默认自动推进，只在偏差时手动修正 |
| **电视装不下试卷** | 阅读理解 400+ 字一屏放不下，数学要草稿纸，英语听力跟音量打架。题库要按"15 秒答完的单点知识"重做，覆盖的是知识点不是题型 |
| **日期可刷额度** | 现有 `dayKey(wall)` + `today != day → rollOver()`，日期前进/回拨都能触发重置，需加单调校验 |
| **投屏可能不计时** | 手机投屏是孩子最常用的路径，投屏 App 未必在视频白名单内，需逐台实测 |

## 五、地基：知识点体系要先定

错题统计、相似题生成、进度匹配三者共用一套标签体系，schema 必须在写第一行代码前定死：

```
学科 → 册 → 单元 → 知识点 → 考察角度（识记 / 理解 / 应用）
题目 ↔ 知识点 多对多，附 difficulty / 题型 / 验证状态 / 干扰项质量分
```

规模估算：5 科 × 8 单元 × 5 知识点 ≈ 200 个知识点；每个 × 3 角度 × 2 难度 ≈ 1200 题，要支撑"错题换新题不重复"，**起步 2000–3000 题**。

**AI 生成题的底线**：数学题必须能被程序验算（符号计算再跑一遍），算不通的不入库。一旦出现"正确答案被判错"，孩子不会再信任这个系统，整个机制就废了。语文/英语的语义题没有自动验证手段，必须人工抽检，并把"最恰当的一项"这类有争议题型剔除。

## 六、还没回答的

教材版本（尤其英语是否湘少版）、通过规则、每日上限、重试冷却、基础额度形状、未学过的题怎么处理、三套限制是否保留、投屏是否计入——共 12 项阻断性决策，见 `docs/待定事项-做题换时长.md`。

另有一条不技术的提醒：用"看电视"奖励"做题"长期会削弱学习的内在动机（过度理由效应）。把做题包装成每日挑战/知识闯关、加连续天数与徽章，能弱化交易感，成本很低。
