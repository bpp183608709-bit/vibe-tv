## 1. 要解决的问题

原来「每天一个固定总时长」在家里用不起来：工作日孩子只有少量时间，周末有大把时间，一个数字两边都不合适。

新方案把控制从**配给制**改成**赚取制**：每天有基础额度（如 1 小时），用完以后靠做对一组题换时长，或家长输密码加时长。

这个方向是对的，但「赚取制」的安全性只取决于一件事：**答题结果能不能被伪造**。配额是写在本地的数字，赚来的额度却来自一个不可信的客户端——这是它和原来最本质的差别，也是所有架构决策的出发点。

完整论证见 `notes/04-做题换时长-方案评审.md`。

## 2. 已经拍死的架构结论（不要在新对话里重新讨论）

**结论一：加时长不能发生在本地。**
「电视做题 → 本地判分 → 本地加额度」等于把印钞机放进孩子房间。APK 可拆包、数据可改、系统时间可改。

链路固定为：

```
电视请求题组 → 服务端出题（知识点标签 + 去重）
  → 孩子作答 → 服务端判分
  → 通过则签发一次性签名凭证（时长 + 有效期 + 设备绑定）
  → 电视离线验签，兑换成当天额度
```

**结论二：复用现有两个概念，不改签名。**
- `WatchTicket` 从「家长手动发票」扩展成「服务端签票」，形态不变；
- `Parental.extendDaily(extraMs)` 写入的 `dailyExtraMs` 本来就是「当天有效、跨天清零」，与凭证语义天然对齐，**这一行不用改**。

**结论三：断网时的失败模式是可接受的。**
已换到的时长照样能用（凭证在手），没网换不了新的。另需本地常备 2–3 组预取题——API 挂掉当天孩子只剩基础额度，是灾难级体验，家长会直接关掉功能。

**结论四：密码那条路必须设次数上限。**
「做题优先、密码兜底」靠界面排序实现不了：只要有一条更省力的路，孩子一定走那条。唯一有效的手段是限制密码每天加时长的次数（建议 2 次）。

> **2026-11-11 推翻**：户主选「不限次数」。家里是家长与孩子高频交替，限制次数只会逼家长反复操作；而"更省力的路"这个论证成立的前提是孩子拿得到密码。改成「额度一个账、上限分两种」（密码只动分钟数，不动做题的 3 次/90 分钟，见 `docs/QUIZ.md` §2）。

**结论五：AI 生成题必须能被验算。**
数学题用符号计算（Python sympy）复算一遍，算不通的不入库。一旦出现「正确答案被判错」，孩子就不再信任这套机制，整个功能作废。语文/英语的语义题没有自动验证手段，只能人工抽检，并把「最恰当的一项」这类有争议题型剔除。

**结论六：投屏必须计入。**
已经改好 `PlaybackSignal.VIDEO_APPS` 加了三个投屏接收端包名，**已提交（`78ebb6d`），但未编译、未装机、未真机验证**（见第 9 节）。

## 4. 与现有工程的三个冲突（必须先解决，否则代码写不下去）

1. **状态机是三态**（`Normal` / `Interval` / `DailyLimit`）。新需求要加「赚取中」，且做题界面必须明确不计时——否则孩子在做题页待着也在烧额度，等于惩罚他做题。
2. **`dailyMinutes = 0` 现在表示「不限」**，与「基础 1 小时」的语义直接打架。要定清楚：不限额度时做题面板还出不出现。
3. **`WatchTicket` 是纯内存 `object`**，重启即失。做成凭证必须落盘 + 防篡改（HMAC 或设备绑定，不需要 PKI）。

另有一条历史结论要注意：`docs/PARENTAL.md` 第 6 阶段论证过「手机页不做」，理由是「孩子也能摸到同一台手机，收益不抵风险」。新的**公网 H5** 把这个风险放大了，鉴权标准必须比原来的局域网 token 高一个量级：独立账号 + 二次确认 + 设备绑定 + 操作留痕。

## 6. 数据模型草案（写第一行业务代码前要定死）

知识点体系是地基：错题统计、相似题生成、进度匹配三者共用一套标签，schema 定晚了三处都要返工。

```
学科 → 册 → 单元 → 知识点 → 考察角度（识记 / 理解 / 应用）
题目 ↔ 知识点 多对多，附 difficulty / 题型 / 验证状态 / 干扰项质量分
```

规模：5 科 × 8 单元 × 5 知识点 ≈ 200 个知识点；每个 × 3 角度 × 2 难度 ≈ 1200 题。要支撑「错题换新题不重复」，**起步 2000–3000 题**，低于这个数做不出不重复。

题面按电视可答设计：15 秒能读完的单点知识，正文 ≤ 120 字；**不做** 400 字以上阅读理解、几何/统计图、英语听力。
