# 错题训练：设计说明

> **状态**：D1–D6 已全部由户主定案（2026-11-15）。本文是设计说明，**不是已实现的规格**。
> **与既有文档的关系**：`docs/QUIZ.md` 管「做题换时长」的现状与实现，`docs/PARENTAL.md` 管家长模块行为。
> 本功能是它们的下一层：**决定「出什么题」，不改「换多少时长」**。定案后，行为条款补进 `docs/PARENTAL.md`，
> 本文留作设计依据与决策出处。
> **一句话**：把「错题」当作一等公民——电视上错的、试卷上错的，都折算成知识点的「不牢固度」，
> 不牢固度只改两件事：**这个知识点在统一出题逻辑里被抽中的频次权重**，以及
> **一组 5 题里「当前单元 / 前 2–3 单元 / 错题训练」三段的比例**；生成多少相似题也由它定。
> **对孩子的表达口径（v1.4 硬约束）**：电视端**不呈现任何**薄弱知识点、知识点强化练习相关信息——
> 没有知识点名、没有次数、没有进度、没有提示文案（连中性文案也不行）。孩子能感知到的只有两个事实：
> **某类题出现得多了一点；做对的次数多了，它们就变少了**。至于为什么变多、是哪些知识点、还剩几次，
> 一律不解释、不提示、不暗示。

## 1. 现状：这台电视上已经有什么

以下是从代码里读出来的事实，不是推测。

| 已有件 | 落点 | 与本功能的关系 |
|---|---|---|
| 知识点树 | `server/content/curriculum/grade6-up.json`：3 科 16 单元 **30 个知识点**，`verified=false` | 本功能的统计主键，**不新建** |
| 出题 | `server/app/picker.py`：当前单元 → 前两单元 → 其余三层；排除 7 天内同题；`wrong_count` 降序加权；≥2 科；≤2 题/知识点；5 题 | 本功能的加权点在这里 |
| 判分 | `server/app/grade.py`：服务端唯一权威，`⌈0.8n⌉` 通过，Fraction 等价比较，幂等 | 掌握度的事件源在这里 |
| 错题信号 | `topic_signal`：`right_count / wrong_count / unknown_count / unknown_streak` 四个纯计数器 | **只有计数，没有「掌握度」**，也没有衰减与档位 |
| 错题明细 | `quiz_answer`：每题的对错、孩子选了啥、`flagged_unknown` | 已有「来源一」，但只存电视做的题 |
| 手机端 | `server/web/` 四 tab：今日 / 周报 / 错题本 / 设置；邮箱账号 + 多电视绑定（`docs/ACCOUNT.md`） | 「来源二」的入口与确认页落在这里 |
| 题库 | 86 道模板生成种子题；`question.template_key + param_hash` 唯一，数学过 sympy | 池子太小，是本功能第一个硬约束 |
| 模板覆盖 | 30 个知识点里 **19 个有生成模板**（数学 13/16、英语 4/7、语文 **2/7**） | 决定「生成相似题」不能只靠大模型 |

**结论**：链路、账本、验签、家长端都在，缺的是三样东西——**一张错题表、一个掌握度、一个生成器**。

## 2. 四个产品判断（先说结论）

### 判断一：巩固不能新增时长来源

「越不牢 → 题越多 → 做得越多」，如果每多做一组就多给 30 分钟，这套机制立刻变成印钞机：
孩子只要故意做错，就能把每天的题池当成时长矿。现有 `3 次 / 90 分钟` 是刻意对齐的两个上限
（`docs/QUIZ.md` §2），不能被绕过。

**户主定案（D1）：不额外给时长，纳入统一出题逻辑一起设计，只是越不牢固的知识点出题频次权重越高。**

这条比 v1.0 的方案更省：**没有「巩固组」这个新概念，也没有「池」**。5 道题还是一组，通过线、奖励、
每日 3 次 / 90 分钟全部原样；变的是「这 5 道题从哪来」——薄弱知识点在同一套抽题逻辑里权重更高。

「做得更多」因此是**自然结果而不是新规则**：权重高 → 出现频次高 → 同一知识点要答对更多次才过关（§5.3）。
这顺带堵掉了「故意做错换奖励」的动机：题变多变难，时长不变，装傻只有坏处。

对孩子来说，这条判断的可见形态只有一个：**同一类题出现的次数变了**。没有「巩固」这个概念，
没有「额外加练」的动作，也没有「你错了所以要补」的因果——他连这是被安排的都不知道（判断五）。

### 判断二：掌握度必须是加法，不能是模型

可解释性在这里不是锦上添花，是**家长的信任来源**：家长要看得懂「为什么这周分数乘法老出现」、
「还要盯多久」。任何需要阈值调参、样本量不足就失真的概率模型（BKT / IRT 一类），
在「一个孩子、30 个知识点」的量级上既训不出来，也解释不清，还无法验收。

**所以：掌握度是事件权重的累加，每个权重是人写死的常数，全表可回放。**

> 注意这个解释只对家长发生。孩子那边不解释、也不展示——见判断五。同一条模型，
> 在家长侧是可核对的账单，在孩子侧是**不可见的调度参数**。

### 判断三：试卷照片是「证据」，不是「题目」

把试卷照片直接切出来给孩子在电视上做，看着最省事，实际是灾难：照片会歪、会糊、会带老师红笔、
会带姓名学号；题干可能是作图题、长阅读、表格——这三类 `docs/QUIZ.md` §6 早就明确不做。

**所以：照片只用来「证明这个知识点错了」，不进入出题。孩子做的是由此生成的相似题。**
这条同时解决了隐私（照片可 30 天删干净，不影响题库）与体验（屏幕上永远是干净的 960×540）。

### 判断四：三段比例要跟着薄弱面走，但只有两个旋钮（D6）

出题仍然是原来的三层：**当前单元 → 前 2–3 单元 → 错题训练**（§6）。但三段占比不能写死：

- 写死「3 : 2 : 0」→ 薄弱点堆了五个的时候，机刷题位不够，孩子每天都在错过的东西上重复浅做；
- 写死「2 : 2 : 1」→ 孩子一个错题都没有的时候，也要硬塞一道复习题，凭空浪费一个题位（还会破坏零回归）。

所以比例由一个「**薄弱面**」驱动：**规模 n（L1+ 知识点数）× 最深档 Lmax**，映射到 S0–S3 四档。

**但三个比例里只有两个是旋钮。**一组固定 5 题，C（当前单元）+ P（前 2–3 单元）+ R（错题训练）= 5，
给定任意两个，第三个就定了。我选 **C 与 R 做旋钮、P 做余量**，理由：

| 旋钮 | 能控什么 | 为什么是它 |
|---|---|---|
| **C（当前单元上限）** | 孩子跟不跟得上学校进度 | 跟课是最不可让步的诉求，必须留下限（≥2 题；「≥2 科、每科 1 题」由 `picker.py` 的轮转单独保证，不靠 C 配额） |
| **R（错题训练题数）** | 补不补得上过去的洞 | 这是本功能的本体，必须能独立放大 |
| P（前 2–3 单元） | 余量 | 它本来就是现状里的「补位层」（`tier=1`），不做旋钮反而诚实 |

**为什么不连续调**：家长要能一句话说明白「你孩子有 4 个知识点不牢，所以一组里有 1 道是补错题的」，
连续函数既解释不了也验收不了。四个档位对应四句人话，也对应四个回归用例。

### 判断五：电视是娱乐场景，一个字也不说（D5 + v1.4 口径）

电视这块屏的用途不是「让孩子知道自己在进步」，而是**换到看动画片的时间**。所以本功能在电视端
不是「少说一点」，是**一个字也不说**：

| 谁 | 看到什么 |
|---|---|
| 孩子（电视） | **只有题目本身**。某类题出现得勤一点；做对的次数多了，它们就慢慢变少。没有知识点名、没有次数、没有进度条、没有提示 |
| 家长（H5） | 分数、档位、再答对几次、加减分流水、当日配比、本周该讲哪 1–2 个 |
| 服务端 | 心里有数，但一个字段都不下发给电视 |

**孩子侧的感知通道只有一条：频次。**这是刻意保留的唯一线索——它是「做题」这个动作自带的属性，
不需要任何额外表达：一组 5 题里同类题从 0 道变成 1 道，孩子自然会觉得「这类题最近老出现」；
连着做对几次之后它又退回 0 道，感觉就是「不来了」。**这个闭环不需要一句解释也成立**，
而任何解释都会把它从「题目变多了」变成「我被布置了作业」。

**为什么连中性文案都不给。**「今天有 2 道是复习题」这种句子看着无害，实际干了两件事：

1. 它把「复习」这个词塞进了一个娱乐场景——一旦孩子意识到自己在做题时会被告知「这是为了你好」，
   「做题 = 学习任务」的感觉就建立了，抵触从这里开始，而且建立之后很难退回去；
2. 它会立刻引出下一个问题「为什么是我？哪些要复习？还剩几道？」——而这些问题只要回答一个，
   就等于把薄弱知识点名单交出去了（不管用什么措辞）。

所以口径是**不解释，不告知，不提示**。孩子不需要知道自己哪些知识点不牢，只需要在不断的做题里
润物细无声地补强。

**顺带的好处（不是主要理由，但很实在）**：电视端协议一行都不用改。原来「再答对 N 次」要在题面顶部显示，
就得让 `/v1/quiz/next` 每道题多带一个 `review` 字段；`/grade` 还得回一段 `mastery`。现在两个字段都不下发，
电视端仍是「取题 → 答题 → 交卷」，与今天完全一样。**这省掉 P0 里唯一的电视端改动**，
也少了一条「两端各算一遍 N、迟早不一致」的隐患。

**代价必须写在这里，而不是绕过**：**RK-13（孩子放弃）失去了「告知进度」这个缓解手段。**
孩子会遇到「怎么又是分数乘法」，屏幕上没有任何东西告诉他这是自己挣回来的、还剩几次。
能兜住这个风险的只有结构本身——组内同知识点 ≤2 题、单知识点每日 3 题上限、连错 5 次停 3 天。
所以 §12 加了两条指标专门盯这件事；**但兜底方向只能是调服务端参数（降频、放宽上限、延长暂停），
不是回头往电视上加提示**——见 §16。

```
        ┌──────────── 来源一：电视做题 ────────────┐
        │  quiz_answer.is_correct = 0             │
        │  （已在库，判分时同一事务写入）           │
        └───────────────┬─────────────────────────┘
                        │
        ┌──────────── 来源二：手机拍试卷 ──────────┐
        │  拍照 → OCR → 家长逐题确认 → 错题记录     │
        │  （识别不出来也要能录：只选知识点 + 数量） │
        └───────────────┬─────────────────────────┘
                        ▼
              ┌───────────────────┐
              │  知识点归因 topic  │  一题一个主知识点（E4）
              └─────────┬─────────┘
                        ▼
              ┌───────────────────┐
              │  掌握度 M ∈ 0..100 │  ← mastery_event 流水，可回放
              │  档位 L0 / L1 / L2 / L3
              └─────────┬─────────┘
                        ▼
              ┌───────────────────┐
              │  生成相似题（补齐）│  目标题量 ∝ 档位：0 / 5 / 7 / 10
              └─────────┬─────────┘
                        ▼
              ┌───────────────────┐
              │  电视出题：三段配比 │  5 = C + P + R，S0–S3 四档（§6）
              │                   │  R 段内按权重抽，更弱更常被选中
              └─────────┬─────────┘
                        ▼
              孩子做对 → M 下降 → 权重降 → 出现变少 → 配比回落
              孩子做错 → M 上升 → 权重升 → 出现更多 → 配比升高
                        │
                        └──────────────► 回到「掌握度」（闭环）
```

> 这条链**对孩子完全不可见**（§10）。他这一侧只有两个可见事实：这类题出现得勤了；做对几次之后它们少了。
> 图上所有方框、分数、档位、配比，都只存在于服务端与家长的屏幕上。

## 4. 两个来源怎么进来

### 4.1 来源一：电视错题（零新增采集）

判分时已经在同一事务里更新 `topic_signal`（`grade.py._bump_topic_signal`）。本功能只做一件事：
**在同一个事务里追加一条 `mastery_event`**，并把「这次错」写进 `wrong_item`（`source='tv'`）。

不新增任何客户端上报，不新增任何请求——这是最便宜的一半，也是先做的一半。

### 4.2 来源二：试卷错题（D2：本期只做手选，OCR 单独立项）

> **本节的前半（拍照 → OCR → 确认页）已按 D2 移出本期**，留给那个独立功能当输入；
> 本期只实现其中的**降级路径**：家长在手机上选一个知识点 + 错了几道，20 秒录完。
> 下面四个决定仍然成立，它们描述的是整条链（含未来的 OCR），不是本期范围。

```
本期：选知识点 + 错几道 ────────────────► 入库 → 加成 → 生成
将来：拍照(1–6 张) → OCR → 草稿 → 家长确认 ─┘   （独立立项）
```

四个已定下的产品决定（含为将来 OCR 留的约束）：

| 决定 | 理由 |
|---|---|
| **入口只在手机端，且必须登录** | 孩子拿不到手机就不会乱拍；试卷带孩子个人信息，不能有匿名入口 |
| **识别结果必须家长确认才入库** | 错题判定错一次 → 生成一堆垃圾题 → 孩子对这个功能的信任一次就崩，之后做对也不信 |
| **必须有「只选知识点、不录题面」的降级路径** | OCR 一定会有识别不了的卷子（手写、表格、作图）。降级路径让功能在识别很差时**依然可用**，而 MVP 可以直接先做这条 |
| **照片只是证据，30 天后自动删** | 儿童个人信息最小化；删照片不影响已生成的题与已算的掌握度 |

**确认页的形态**（目标：一份 10 道错题的卷子 ≤90 秒确认完）：

```
┌ 确认这次错的题 ─────────────────────┐
│ 共识别 11 道，已默认勾选 6 道有红叉的   │
│                                        │
│ [缩略图] ① 一根绳子长 3/4 米，用去…    │
│   知识点 [分数乘法应用题 ▾]  置信度 高  │
│   ☑ 算错题            [丢弃]           │
│                                        │
│ [缩略图] ② …（置信度低 → 黄底提示）    │
│   知识点 [请选择 ▾]  ⚠ 没认准，请挑一个 │
│   ☑ 算错题            [丢弃]           │
│                                        │
│ 识别不出来的，只记知识点也行：          │
│ [+ 添加：选知识点 + 错了几道]           │
│                                        │
│           [ 全部确认并生成相似题 ]      │
└────────────────────────────────────────┘
```

## 5. 掌握度模型

### 5.1 事件权重（全部写死，可回放）

| 事件 | ΔM | 理由 |
|---|---|---|
| 电视答错（未标记「没学过」） | **+12** | 一次错就是一次明确信号 |
| 电视答对 | **−10** | 错一次要 1.2 次做对才抵回来；不对称是刻意的，错比对付 |
| 标记「没学过」 | **0** | B7 的既有规则：不惩罚说真话，也不加成 |
| 试卷错题，同知识点当日第 1 道 | **+20** | 卷子上的错比电视上的一次更有代表性 |
| 试卷错题，同知识点当日第 2 道起 | **+8** | 边际递减：一份卷子不该把一个知识点顶满 |
| 同知识点连续第 2 次答对（计数随即归零重计） | **额外 −10** | 给「连着做对」一个可见的加速：**一对连对共 −30**，也让 L3 的过关次数从 8 降到 6 |
| 家长手动调整 | **±10 / 次，必留痕** | 兜底：家长知道孩子其实会，只是那天状态差 |

`M = clamp(0, 100, Σ ΔM)`，整数。

### 5.2 档位、频次权重、目标题量（D1）

| 档 | M | 名称 | 权重 w | 错题段内相对概率 | 目标可用题量 | 单知识点每日上限 | 预估过关 |
|---|---|---|---|---|---|---|---|
| L0 | 0–11 | 牢固 | 1.0 | 不进错题段 | 0 | — | — |
| L1 | 12–35 | 需巩固 | 2.0 | 2 倍 | 5 | 3 题 | 约 1 天 |
| L2 | 36–70 | 不牢 | 3.0 | 3 倍 | 7 | 3 题 | 约 1.7 天 |
| L3 | 71–100 | 很弱 | 4.0 | 4 倍 | 10 | 3 题 | 约 2.7 天 |

- **权重**只决定「错题训练段该抽哪个知识点」，不改题数、不改通过线、不改奖励；
- **目标可用题量**是生成器的补齐目标（§7），不是「待过关的池」——孩子做掉的题不会从池里消失，
  只会因为 M 下降而降低权重；
- **每日上限**是单独一条护栏，不是权重的一部分（§5.4 第 2 条），也是上表最后一列的推导前提；
- 四个量都由 M 单点决定，改档位阈值时只需改这一张表。

**目标题量怎么算出来的（0 / 5 / 7 / 10）**：它由「过关要几道题」反推，而不是拍个数。
按 80% 正确率（正好是通过线）估：L1 需 2 次答对 → 约 3 道题 → 目标 5；L2 需 4 次 → 约 5 道 → 目标 7；
L3 需 6 次 → 约 8 道 → 目标 10（各留 2 道缓冲，因为 7 天不重出的窗口比一次过关更长）。

**为什么权重是 1 / 2 / 3 / 4 而不是连续值**：家长要能一句话听明白「很弱的比需巩固的多一倍概率」，
四个档位对应四句人话，也对应四个回归用例。连续函数既解释不了，也没法验收。
（孩子那边不知道有权重这回事，只感觉到「这类题变得多了一点」——见 §10。）

**边界为什么这么切**：一次电视答错 = +12，必须立刻离开 L0（否则家长端出现「孩子刚做错，这里还写着牢固」，第一眼就穿）。
一次试卷错 = +20 落到 L1，一份卷子错 3 道同知识点 = 20+8+8 = 36 进 L2——这与「错了三道还不算不牢」的常识一致。

### 5.3 过关：由 M 直接推出「再答对几次」

D1 去掉「池」之后，「有尽头」不能再靠池耗尽来保证，只能由 M 直接算：

```
N = ceil((M - 11) / 10)      // 每答对一次 -10，连续第 2 次再额外 -10
```

| 起点 | H5 显示「再答对 N 次」 | 实际（含连对加成） | 预估题数（80% 正确率） | 预估天数（日上限 3） |
|---|---|---|---|---|
| L1（35 分） | 3 次 | 2 次 | 3 道 | 1 天 |
| L2（70 分） | 6 次 | 4 次 | 5 道 | 1.7 天 |
| L3（100 分） | 9 次 | 6 次 | 8 道 | 2.7 天 |

**显示值取不含连对加成的保守值**：做到了会比说的更早过关，这是惊喜；说 2 次却要 3 次，是骗人。
这条规则**只作用于 H5**（D5）——家长看到的次数可以保守，孩子那边不显示任何次数。

**「这个知识点多久能清掉」由此落地（只有家长看得见）**：L3 的 6 次答对 ≈ 8 道题（受每日 3 题上限约束）。
这是该知识点**独享或近乎独享** R 段时的最快节奏 → **2.7 天**；多个薄弱点共享 R 段时按 §6.8 折算，最慢约 5–6 天。
这个节奏的意义在于**家长能不能在一周内看到一个知识点过关**——看不到变化，家长就会认为这套东西没用，比孩子放弃来得更早；
反过来，L1 只需 1 天就能清掉，所以「拍照添加错题」不会变成家长的无效操作。

> 这里刻意不写「孩子在电视上要做几次」：孩子侧没有次数这个概念，只有「做对了，题就少了」。
> 把次数当成孩子的目标，等于替他把做题变成了刷进度（见 §10）。

### 5.4 防止「做不到」和「白做」（取代 v1.0 的补题轮次）

没有池了，补题轮次这条规则一并取消，换成三条：

1. **题不够时不硬凑**：可用题量不足目标题量时，权重按 `可用题量 ÷ 目标题量` 打折
   （目标 10 只有 5 道 → 权重新 0.5×），避免连续几组反复出同两道题——反复出同一道比少出更伤信任。
2. **单知识点每日 3 题上限**：同一知识点在同一 `day_key` 内被选入错题段的次数封顶 3 题，
   超出后该题位让给次弱知识点；四个都满则题位**归还给课程段**（总题数仍为 5，不浪费）。
   这是「弱一点多练」与「不把同一个知识点塞满一天」之间的平衡点。
3. **连续错 5 次**该知识点的题 → 暂停 3 天不进错题段，家长端提示
   「分数乘法这几组一直没做对，可能需要你讲一下」。这是「孩子卡住」的唯一出口。
4. **不做时间衰减**：长期没练的知识点等级不变，M ≥ 12 仍进错题段（复习本就该跨单元）。
   理由：衰减参数无法验收，且会让家长看到「明明没练却越来越差」的困惑。

### 5.5 与「没学过」的关系（堵一个洞）

`flagged_unknown` 是孩子自己点的。若「答错 + 标记没学过」以标记为准，孩子学会了先点标记就免练。
**规则**：一道题答错且标记「没学过」时，掌握度按「答错」计（+12），`unknown_count` 照旧累加用于通知家长；
只有**答对且标记没学过**才按 0 计。试卷来源的错题不受「没学过」影响（家长确认的，孩子改不了）。

## 6. 出题：三层结构不变，比例可调（D6 定案）

D6 的答复是：「出题还是遵循原来当前单元 + 前 2–3 单元 + 错题训练的策略，只是这三者的比例可以根据薄弱知识点规模及薄弱知识点整体严重程度调整；挑选训练错题时，更薄弱的知识点错误被选中的概率更高。」

所以 **`picker.py` 的三层结构一行不改**，只在它外面加两件事：**一个段配额** 与 **一次加权抽样**。

### 6.1 一组 5 题的三个来源

```
一组 5 题 = C + P + R                （C + P + R = 5，恒定）
├─ C 课程段·当前单元      tier = 0，沿用现状排序（wrong_count 降序 → last_seen → 随机）
├─ P 课程段·前 2–3 单元   tier = 1，现状是前 2 个单元；S3 时放宽到前 3
└─ R 错题训练段            M >= 12 的知识点下的题；跨单元，不受 tier 限制；按 w 加权抽
```

「前 2–3 单元」落成常量 `PREV_UNIT_WINDOW`：S0–S2 取 2（与现状一致），S3 取 3。
**S0 必须取 2**，取 3 会立刻破掉零回归（§6.5）。

### 6.2 薄弱面 → 配比档位（两个维度，取较重者）

| 规模 n（L1+ 且抽得动的知识点数） | 档位 | 最深档 Lmax | 档位 |
|---|---|---|---|
| 0 | S0 | （无） | S0 |
| 1–2 | S1 | L1 需巩固 | S1 |
| 3–4 | S2 | L2 不牢 | S2 |
| ≥5 | S3 | L3 很弱 | S3 |

（两个维度各算一个档位，取**较重**的那个。例子：3 个知识点、其中一个只是 L1 → 规模说 S2，深度说 S1 → 取 S2。）

| 状态 | 触发条件 | C 当前单元 | P 前 2–3 单元 | R 错题训练 | 一句话 |
|---|---|---|---|---|---|
| **S0** | n = 0 | 5（现状贪心） | 余量（实际 0） | 0 | 没有错题，一切照旧 |
| **S1** | 1–2 个，且都只是需巩固 | 4 | 余量（实际 0） | 1 | 加一道错题，别的不动 |
| **S2** | 3–4 个，或出现不牢 | 3 | 余量（实际 0） | 2 | 错题顶到上限，课程留 3 |
| **S3** | ≥5 个，或出现很弱 | 2 | 余量（约 1） | 2 | 再让一道课程题给前段复习 |

**n 的精确定义**（不写死配比就会飘）。同时满足三条才算一个：

1. `topic_mastery.score >= 12`；
2. 该知识点有可用题（`ready_qty >= 1`，且 7 天窗口内还有没出过的题）；
3. 不在 `paused_until` 暂停期内。

条件 2 是关键：没题的知识点抽不到，把它算进规模只会让配额落空，孩子白等一个题位。
家长端显示的是**全部** L1+ 知识点数，所以两侧可能差 1–2，家长端要注明「其中 k 个暂无题可练」，
否则家长会以为系统漏了他刚录的那条。

**为什么严重度取「最深档」而不是平均分**：一个 L3 加九个 L1，平均分看着「中等」，
但那个 L3 才是真问题。平均值会稀释最需要被处理的那一个。

### 6.3 只有两个旋钮，P 是余量

5 题固定，`C + P + R = 5`，给定 C 与 R，P 自动确定。选 C 与 R 做旋钮的理由见 §2 判断四。

表里 P 在 S1、S2 都是 0，不是漏写：4+1、3+2 都已经占满 5 个题位，P 没有位置；
只有 S3（2+2=4）才空出一格给前段复习。**这不影响「三段比例可调」**——四档配比
`5:0:0 → 4:0:1 → 3:0:2 → 2:0:2(+1 前段)` 本身就是四种不同的三段占比，只是它由两个旋钮驱动。

**为什么 R 封顶 2**：5 题里 R 到 3 时，`picker.py` 的「≥2 科、每科 ≥1 题」轮转就会把某一科的
课内题挤掉，一组题里会连着出现同类题、新内容明显变少——孩子说不出原因，只觉得「越来越像同一套题」。
重度状态要加的是强度（权重、日上限），不是继续加题数。这条封顶同时也是 §10「不靠文案解释」的结构性保障。

### 6.4 取题顺序（实现口径，直接决定零回归成不成立）

```
1. 读当日快照 (state, c, r)，p = 5 - c - r
2. R 段先取：候选按 w 加权无放回抽 min(r, 可抽数) 题
   约束：组内单知识点 ≤2、当日 ≤3、7 天不重出、未暂停
3. C 段再取：沿用现状 subject 轮转（每科先 1 题），但 tier=0 的题数封顶 c
4. 剩余题位按现状补：tier=1（窗口按 state 取 2 或 3）→ tier=2 → 仍不足时回吞给 C 段 → 再不足抛 NotEnoughQuestions
5. 最后 shuffle（现状做法，避免「第三题永远是英语」）
```

- **R 段必须先取**：定向题不先锁名额，就会被第 3 步的「每科轮一题」挤掉。这是最容易写错的一处。
- **配额是目标不是墙**：C 段候选不足（该单元题少、都做过）时可超 `c`，先保课程；
  P 段无候选时那一格退回给 C 段——R 不再扩，硬上限就是 2。
- **R 段不排除当前单元的题**：薄弱点就在当前单元是最常见的情形，排除它等于把最该练的题剔掉。

### 6.5 零回归（硬要求，写成用例）

`M` 全为 0 → state = S0 → `c = 5, r = 0` → 第 2 步空转、第 3 步不封顶、第 4 步与现状完全一致。
用例只有一句：**同一份库、同一 `now_ms`，改造前后 `pick_group` 必须返回同一串 `question_id`。**

这条守的不是洁癖：电视上这套出题已经跑通，改坏了是全家一起受影响，而且没有别的通道能替代。

### 6.6 配比快照：一天一算，不随每组抖动

配比存在 `daily_state`（和「3 次 / 90 分钟」同一行，`day_key` 同源），**每天第一组时算一次，当天不再变**。

- **为什么不实时算**：孩子连错两道就让 R 从 0 跳到 1 再跳回 0，一组里题目来源会忽多忽少，
  看着像系统在抽风；也不利于复现。
- **当天新增的薄弱点有一个例外**：家长当天录了错题、或孩子当天第一次错某知识点
  （`last_event_at` 落在今天且 M ≥ 12），即使当日 `r = 0`，也可临时占 **1** 个 R 题位。
  没有这条，P2 验收里的「录完下一组立刻出现该知识点的题」就不成立。
- **降档不设延迟**：第二天快照自然回落，不需要额外规则。

### 6.7 R 段的加权抽样（更弱 → 更常被选中）

- 权重 `w = 2 / 3 / 4`（L1 / L2 / L3），再乘供给折扣「可用题量 ÷ 目标题量」；
- 无放回抽取，种子 `random.Random(now_ms)`（沿用现状），同一秒可复现；
- 效果：1 个 L3 + 1 个 L1 时，L3 占 `4/(4+2) = 67%`；若按个数平均分只有 50%。
- **为什么不按「错误次数」加权**：`wrong_count` 是终身计数，老错题会永久压制新错题；
  M 有下降通道，能跟着孩子的进步退场。这也是复用 `topic_signal` 而不复用其权重的理由。

### 6.8 节奏校验：薄弱点越多，每个清得越慢（必须让家长知道）

每组 R 题位 = `r`，每天 3 组 → 每日 R 题位 = `3r`。按 80% 正确率折算（L3 需 8 道题过关）：

| 当天薄弱面 | 状态 | R 题位/天 | 最弱点能分到 | L3 过关 |
|---|---|---|---|---|
| 1 个（L3） | S3 | 6 | 3（日上限封顶） | **2.7 天** |
| 2 个（L3 + L1） | S3 | 6 | 3（封顶） | **2.7 天** |
| 3 个（L3 + L2 + L1） | S3 | 6 | 2.7 | **3.0 天** |
| 5 个（L3 + 4×L2） | S3 | 6 | 1.5 | **5.3 天** |
| 3 个全 L1 | S2 | 6 | 2 | 1.5 天（L1 只需 3 道） |

> 「最弱点能分到」= `3r × w / Σw`，再与日上限 3 取小。上表是估算，用于判断节奏是否可接受。

**这张表要说清一个事实**：一天 15 道题，不可能把 5 个薄弱点一起快速清掉。
所以家长端要显示「本周重点讲这 1–2 个」；知识点详情里报的是**单个知识点**还要几次，
不报全库总数——报总数会变成一张永远清不完的清单。
D5 之后这些数字全部只在 H5 出现，电视上既不报总数也不报单点（§10）。

## 7. 生成相似题：只有一条路（D3 定案）

D3 的答复是「与题库生成方式一致，相似题只是走增量触发（要排除库内相同题目）」。
所以**不做两套生成通道**，本期也不引入大模型自由生成：

```
既有题库生成方式（tools/gen_seed_questions.py）
模板 × 参数 → question(template_key, param_hash) → 数学过 sympy → verify_status
        ↑
相似题 = 完全同一套东西，只是触发方式从「批量灌库」改成「按需补齐」
```

### 7.1 增量触发：只在不够时补

```
该知识点 M 升档 → 目标题量变化（0 / 5 / 7 / 10）
              → 若 可用题量 < 目标题量：落一条 gen_task(need = 目标 - 可用)
              → worker 跑模板扩参，够数即停
              → 写 question + 回填 gen_task.done_count
```

触发时机三个：**电视交卷后若升档**、**家长确认错题后**、**每日一次补齐**（兜底，处理上次失败或漏掉的）。
`POST /v1/quiz/next` 里不做生成——出题接口不该等一次模板展开。

### 7.2 排除库内相同题（D3 明确要求的三道闸门）

| 闸门 | 落点 | 现状 |
|---|---|---|
| 入库唯一约束 | `UNIQUE (topic_id, template_key, param_hash)` | **已有**，参数重复直接写不进去 |
| 生成前查重 | 取该知识点已有的 `(template_key, param_hash)` 集合，生成时跳过 | 新增（几行查询） |
| 出题时排除最近 7 天同题 | `REPEAT_WINDOW_DAYS` | **已有**，不变 |

「换个数字的伪相似题」用第一道闸门挡不住（参数不同就算新题），但它至少是**不同的题**，
孩子不会觉得被耍。真正要防的是同一道题反复出现，那是第三道闸门的事。

### 7.3 一个必须提前说的阻塞：8 个知识点没有模板

**30 个知识点里，语文 5 个、英语 3 个没有参数化模板**（数学 13/16、语文 2/7、英语 4/7）。
D3 定了只走模板，就意味着这 8 个知识点**一道相似题也生成不出来**。

所以 P1 的前置工作不是「接大模型」，而是**把这 8 个模板补出来**——纯人工活：
每个知识点一个参数化模板 + sympy 验算（数学）或答案集（语文英语），按现有 `gen_seed_questions.py` 的写法加即可。

**在这些模板补齐之前，语文英语的错题只能加掌握度、不能出题。** 这条必须如实告诉家长，
不能让他以为「拍了卷子孩子就有题做」。提示**只出现在 H5**（录入页与该知识点详情），
**电视端不做任何提示**——「这个知识点暂无题可练」属于典型的系统状态说明，一旦上屏就在告诉孩子
「你被专门安排了练习」。电视那边的表现就是「什么都没发生」（§10）。

## 8. 数据模型

新增 5 张表、改 3 张表（`question` / `quiz_session` / `daily_state`）。两份 DDL 必须同步（`tools/check_schema_parity.py` 会拦）。

```sql
-- 错题记录：两个来源的统一落点
CREATE TABLE wrong_item (
  id            TEXT NOT NULL,          -- ULID
  device_id     TEXT NOT NULL,
  source        TEXT NOT NULL CHECK (source IN ('tv','paper')),
  question_id   INTEGER NULL,           -- tv 来源指向 question；paper 来源为空
  paper_id      TEXT NULL,              -- paper 来源指向 paper
  topic_id      INTEGER NOT NULL,
  stem_text     TEXT NULL,              -- 识别文本或原题干（给孩子看到的是生成题，不是这条）
```

## 9. 接口

**D5 之后，电视端一个字段也不加。** 这是本节最重要的结论：老 APK 不用改、不必重新发版，
进度信息改由手机端拉取。

| 方法 | 路径 | 变化 |
|---|---|---|
| POST | `/v1/quiz/next` | **不变**。**不下发 `review`**（没有知识点名、没有 `need_right`）；服务端自己知道哪几道是 R 段，直接落 `quiz_session.review_question_ids` |
| POST | `/v1/quiz/{id}/grade` | **不变**。**不下发 `mastery`**；掌握度只写库，由 H5 读 |
| POST | `/v1/quiz/{id}/flag` | **保留路由，但调用方变成 H5**（原来打算放在电视端长按 OK）。理由见 §10 |

手机端（全部走 `account_session` 鉴权，与现有 H5 一致）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/h5/mastery` | 薄弱知识点榜：科目、单元、知识点、分数、档位、再答对几次、最近一次错是哪天；另带当日配比 `mix: {state, n, c, p, r}`。**这是 `need_right` 唯一的出口**（D5） |
| GET | `/v1/h5/wrongbook` | **扩展现有**：加 `source`（tv / paper）、`mastery_score`；分页 |
| POST | `/v1/h5/paper` | 建批次，返回 `paper_id` 与上传地址 |
| POST | `/v1/h5/paper/{id}/shot` | 上传一张照片（限张数、限体积、校验真实图片） |
| POST | `/v1/h5/paper/{id}/recognize` | 触发识别（幂等，重复调不重复排队） |
| GET | `/v1/h5/paper/{id}/draft` | 识别草稿：逐题缩略图 + 文本 + 候选知识点 + 置信度 |
| POST | `/v1/h5/paper/{id}/confirm` | 家长确认（逐题 accept / 改知识点 / reject；可只选知识点） |
| POST | `/v1/h5/paper/{id}/abandon` | 放弃并立刻删照片 |
| POST | `/v1/h5/topic/{id}/adjust` | 家长手动 ±10，必填理由，写审计 |

**幂等**：`confirm` 以 `wrong_item.id` 为准，重复提交不重复加成（`status` 已 confirmed 则跳过）。
**账务一致**：掌握度更新与 `quiz_answer` 写入必须同一事务——沿用 `_bump_topic_signal` 的位置，
扩成 `_apply_mastery_event(cur, ...)`。

**电视响应的禁止清单（v1.4，逐个写进断言）**：`/v1/quiz/next` 与 `/grade` 的响应体里，
**不得出现**以下任何一项——

| 禁止项 | 说明 |
|---|---|
| 知识点标识 | `topic_id` / `topic_name` / `topic` 任何形式；题干里也不许拼进去 |
| 进度量 | `need_right` / `remaining` / `mastery` / `score` / `level` / `weight` |
| 段落标记 | `review` / `review_question_ids` / `is_review` / `segment` / 任何能反推「这题是复习题」的序号 |
| 解释文案 | 「复习」「巩固」「加强」「薄弱」「专项」等词，出现在题面、选项、按钮、结果页任一位置都不行 |
| 隐性信号 | 为 R 段题目单独换配色 / 图标 / 音效 / 排序位置，或改变其交卷后的结果页形态 |

**一切进度字段不下发到电视**（D5）：配比、`need_right`、`level`、分数，全部只经 H5。
电视端因此维持现状的请求/响应形状，不为它增加任何请求。
**但服务端自己得存**：`quiz_session.review_question_ids` 照旧写入（指标靠它分段，不靠电视回传）。

## 10. 电视端：一个字也不说（D5 定案 + v1.4 口径）

**设计目标一句话**：孩子只从「某类题出现的频次」感知到变化，感知不到这是被安排的教学动作。
电视是娱乐场景（换看动画片的时间），不是学习终端；这里不承担任何学习成长向的表达。

> 这条不是新原则，是把既有的 C7 用到底：`docs/QUIZ.md` 早就定了「连续失败 3 次后难度 −1，界面不提示」。
> 难度会变、题会变、频次会变，但**调度策略一概不对孩子解释**。本功能只是把同一条原则扩到知识点维度。

所以「薄弱知识点 / 知识点强化练习」这条线上的**所有**呈现都不做，包括那些看起来无害的：

| 候选呈现 | 做不做 | 为什么 |
|---|---|---|
| 题面顶部「分数乘法 · 再答对 7 次」 | **不做** | 直接交底：既给知识点名，又给倒计时 |
| 结果页「分数乘法 · 已过关」 | **不做** | 同样的交底，只是换了个时机；「过关」还引入了关卡语义 |
| 结果页中性文案「今天有 2 道是复习题」 | **不做**（v1.4 明确） | 一个词就够建立「做题 = 学习任务」的感觉，还会引出「哪些要复习」 |
| 进度条 / 星星 / 徽章 / 「连续 N 天」 | **不做** | 都是把做题变成刷进度，和换时长的动机并列时，会盖掉「快点做完去看动画」 |
| 给 R 段题目换配色 / 加小图标 / 换音效 | **不做** | 隐性信号同样在分类；孩子会总结出「带这个标记的题可以乱选」 |
| 把 R 段题目排到最后 / 排到最前 | **不做** | 排序也是一种标注；且会破坏现状的 shuffle |
| 无障碍朗读里念出知识点 | **不做** | TalkBack 念出来等于念给孩子听 |
| 「这题有问题」长按 OK 入口 | **不做**（移到 H5） | 它不是进度信息，但遥控器长按既难发现又容易误触；家长在错题清单里标更顺手 |

**孩子这一侧只保留两个事实**（都不需要界面表达）：

1. 某类题在一组里出现得比以前勤一点（0 → 1 道，最多 2 道）；
2. 连着做对几次之后，它又慢慢退回 0 道。

这两个事实是「做题」这个动作自带的，不需要一行文案。**它们合起来就是完整的正向反馈**：
做对 → 题变少。孩子不需要知道「为什么当初变多」，也不需要知道「还差几次」——知道这两件事
只会把「做题」翻译成「补课」。

**P0 的电视端工作量是零**：`QuizScreen.kt`、`quiz/` 九个文件、五语言 `strings.xml` 一律不动，
不需要重新发版，也不用再上机验证一次。这是 D5 带来的实质收益，不只是少了三行 UI。

**三条必须遵守的实现约束**：

1. **不要「顺手」把信息透出来**。知识点名不能进题干、不能进选项文案、不能进无障碍朗读文本。
   `/v1/quiz/next` 的响应体禁止字段清单见 §9，逐项写成断言。
2. **N 只在服务端算**。既然两端不是各算一遍，就不存在不一致；H5 每次实时算，`need_right` 不落库。
3. **电视端文案零新增**。任何后续需求想往电视上加「复习 / 巩固 / 加强 / 薄弱」这类词，
   都先改本文档的判断五，再谈实现——不允许在实现里「先加上，回头再讨论」。

**上片前自检（每次改动电视端或接口后逐项过，全部为「否」才可发）**：

- [ ] `tv/` 下有没有新增/修改任何文案、图标、颜色、动效？
- [ ] `strings.xml`（五语言）有没有新增 key？
- [ ] `/v1/quiz/next` 与 `/grade` 响应体有没有多出 §9 禁止清单里的字段？
- [ ] 题面、选项、按钮、结果页有没有出现「复习 / 巩固 / 加强 / 薄弱 / 专项 / 达标」等词？
- [ ] R 段题目在视觉、排序、音效上有没有与普通题不同？
- [ ] TalkBack / 无障碍朗读文本里有没有知识点名或组别信息？
- [ ] 交卷结果页有没有多出一行、换过样式、或与普通组的形态不同？

**这样做的代价（不能只写好话）**：孩子遇到重复出现的一类题时，屏幕上没有任何解释。
他能感知到的只有「这类题最近出现得多」「做对几次之后少了」，感知不到「这是我自己挣回来的作业，还剩 6 次」。
RK-13 因此从「有缓解手段」变成「只有结构性限制」——组内同知识点 ≤2 题、单知识点每日 3 题上限、连错 5 次停 3 天。
§12 加了两条指标盯它；**出现问题的处理方向见 §16——只调服务端参数，不往电视上加任何呈现。**

## 11. 手机端（错题本 tab 升级）

> 界面稿已出图：`docs/mockups/`（7 屏，含深色与空状态），源文件 `wrongbook-h5.html`
> 直接复用 `server/web/app.css`，改样式只改一处；重出图跑 `node docs/mockups/shoot.mjs`。

**D5 之后，这里是薄弱程度的唯一出口，也是唯一的解释入口。** 电视上一个数字、一个字都不提（§10），
所以家长能不能看懂「孩子到底怎么了」全看这几页。这抬高了两处的要求：
总览必须首屏就回答「还有几个洞」，详情必须能解释「凭什么 72 分」。
另外补一条：孩子在电视上看到的每一次「这类题又来了」，解释权都在家长手里——
所以详情页要给家长**一句能直接照着说的话术**（家长说，不是电视说），替代「在屏幕上加提示」这条路。

```
├─ 薄弱知识点 卡片    前 2 条 + 「全部 5 个 ›」→ 薄弱知识点列表
```

**为什么总览只露 2 条而不是全部**：这是个家长一周看两三次的页面，首屏要同时回答

「全部 N 个 ›」把完整榜留给了列表页。

- 每日自动生成题数上限（默认 40 题，估算值，可调）。

少一个开关也少一种「家长以为孩子知道、实际不知道」的误会。

## 12. 指标与口径

| 指标 | 口径 | 目标 |
|---|---|---|
| 主指标：薄弱知识点平均掌握度 | 期末前 `avg(score)` where `level ≥ L1`，按周取快照 | 8 周内下降 ≥30% |
| 复错率 | 同一知识点 30 天内再次答错的比例（分母：30 天内该知识点有答对记录） | ≤25% |
| 三段实际配比 | C / P / R 各自题数 ÷ 出题总数，按周；分段依据 `quiz_session.review_question_ids` 与出题当时的当前单元 | 与当日 state 的目标配比偏差 ≤10pp（超出说明配额一直被候选不足击穿） |
| 供给缺口率 | R 题位被退回（无题 / 暂停 / 日上限）次数 ÷ R 题位总数 | ≤10%（高于就先补模板，不是调配比） |
| 日上限触顶率 | 单知识点当日触到 3 题上限的天次 ÷ 有 R 题位的天次 | 仅 S3 允许 >30%；S1/S2 触顶说明配额或权重不对 |
| 过关率 | 周内从 L1+ 降到 L0 的知识点数 ÷ 周初 L1+ 知识点数 | ≥30%（低于则家长在 H5 上会一直在看同一批知识点） |
| 生成任务完成率 | `gen_task.status = 'done'` ÷ 建任务数 | ≥95% |
| 生成题抽检通过率 | 抽检样本（5%，数学优先）中可用 ÷ 抽检数 | **100%**（判错一次即不可接受） |
| 护栏：错题上报数 | 每周「这题有问题」次数（D5 后来自 H5） | ≤2 / 周，且每条 24h 内处理 |
| 护栏：单组做题时长 | 交卷 − 发题，P50 / P95 | P95 ≤8 分钟（超过说明题太难，会挫败） |
| 护栏：错题段反复率 | 同一 question_id 在 7 天内出现 ≥2 次的比例 | ≤5%（高于则题量不够，先补模板） |
| **护栏：知识点停滞率**（D5 新增） | 连续 14 天 `level ≥ L1` 且 `score` 未下降的知识点数 ÷ 14 天前 `level ≥ L1` 的知识点数 | ≤15%。**这是「孩子悄悄放弃」的主要早期信号**：电视上什么都不显示，孩子开始乱选时，表现就是这个数往上走 |
| **护栏：家长查看率**（D5 新增） | 每周至少打开一次「薄弱知识点」页的活跃家长数 ÷ 有 L1+ 知识点的家庭数 | ≥50%。D5 把全部信息压到 H5，家长不看就等于没有这个功能 |

> **为什么 D5 要加这两条**：进度不对孩子透明，意味着「孩子不愿做」不会再表现为一句抱怨，
> 只会在数据上表现为「题做了但分数不降」。停滞率抓的是这个；查看率抓的是另一端——家长不知道，就不会去讲。
>
> **电视端因此没有「感知类」指标可测**（零表达，没有曝光/点击/提示可见性可埋）。这是有意的：
> 不去测「孩子有没有感觉到」，只测行为——题照做（单组时长、停题率）、分在降（过关率、停滞率）、
> 时长没超（每日 3 次 / 90 分钟）。把感知交给题目频次本身，把验证交给行为数据。
> 两个数一起看：停滞率高而查看率低，问题在通知；两个都低才是孩子那边真卡住了。

> OCR 相关的三个指标（录入完成率 / 确认耗时 / 识别免修改率）随那个独立功能一起验收，不在本功能口径内。

每版本必须有最小数据能力：**「薄弱知识点 × 掌握度变化」这一张表**就是本功能的看板，没有它无法复盘。

## 15. 分期与验收

**D2 定案后顺序更清楚了：先把「掌握度 + 频次权重」跑通，OCR 完全不在本期。**
理由是 RK-05：现在 30 个知识点里 8 个没模板——模板没补齐，题都生不出来，更不用说识别卷子。

| 期 | 内容 | 验收（可测） |
|---|---|---|
| **P0**（1–2 周） | 4 张表 + 3 列改动 + `mastery_event` 权重 + 电视错题自动入错题记录 + 三段配额与配比快照 + R 段加权抽样（**电视端零改动**） | 单元测试：权重累加 / 档位边界 / `clamp` / N 推导 / 幂等 / **S0–S3 四档配比断言**（4 个用例逐个验题数）/ **当日快照跨组不变** / **供给不足时题位退回不丢题** / **响应体不含 §9 禁止清单任一字段**（D5 不得泄露）；**零回归用例**：M 全为 0 时 `pick_group` 返回与改动前同一串 id；**电视端零表达断言**：`tv/` 目录 `git diff` 为空、五语言 `strings.xml` 无新增 key、全仓搜索「复习 / 巩固 / 加强 / 薄弱」不得出现于 `tv/`；真机：同一台电视装旧 APK 仍能正常做题（协议未变），错两道后该知识点在 H5 榜上出现且档位正确 |
| **P1**（2 周） | 补 8 个模板（语文 5 / 英语 3）+ 异步 `gen_task` + 增量补齐 + 三道查重闸门 | 30 个知识点每个都能生成 ≥8 道互不重复的题；数学 100% 过 sympy；同一知识点 7 天内不重复出同题 |
| **P2**（1 周） | 家长端「薄弱知识点」+「错题清单」+ 手动调整 + 手选知识点录入（只选知识点 + 错几道） | 录一条 ≤20 秒；录完下一组立刻出现该知识点的题；家长能看到每个知识点的加减分流水 |
| ~~P3~~ | ~~拍照 OCR~~ | **移出本功能**：D2 定了单独设计后独立实施，另开一份文档 |

**P0 的判据不包含任何电视端改动**（D5）。它应该长这样：同一台电视、同一个旧 APK，做题体验与现在一致——
孩子只会觉得「最近这类题出现得勤，做对几次之后又少了」；而在手机端的「薄弱知识点」里能看到
「分数乘法应用题 · 72 分 · 很弱 · 再答对 7 次」，
并且把那几组做完后，这个分数真的往下走。没有最后这一句（分数真的在降），P0 不算完成——
否则只是把数字画在了页面上。

### D5 定案：对孩子透明，对家长透明

| 谁 | 看到什么 |
|---|---|
| 孩子（电视） | **什么都不变**。没有知识点名、没有次数、没有进度条、没有过关提示、没有「复习/巩固」字样 |
| 家长（H5） | 分数、档位、再答对几次、加减分流水、当日配比、本周该讲哪 1–2 个 |
| 服务端 | 心里有数，但一个字段都不下发给电视 |

**为什么这个划分是自洽的**：这套东西的付费方和监督方都是家长，孩子只是执行者。
给孩子看次数，本质是拿一个他自己不在乎的指标去激励他——他真正在乎的是「还有多久能看电视」，
而那个数字本来就在锁屏上。所以 D5 不是砍功能，是把信息放到了会用它的人手里。

**再加一层（v1.4）**：不只是「不给次数」，而是**不给任何教学语义**。电视是娱乐场景，
一旦屏幕上出现「复习」「巩固」「这个知识点你还不牢」这类词，孩子收到的信号是「我在做题 = 我在被补课」，
抵触情绪从这里建立，而且建立之后每一次出现同类题都会被重新确认一次。
所以正确的做法是让他在不断做题里润物细无声地补强——**他知道题在变，但不知道为什么变、也不需要知道。**

**代价已经记在 RK-13（25 分）**：孩子在电视上遇到反复出现的同类题，屏幕上没有任何解释。
能兜住的只有结构：组内同知识点 ≤2 题、单知识点每日 3 题上限、连错 5 次停 3 天。

**出问题时的调整方向（v1.4 改口径：只调服务端参数，不碰电视端呈现）**

| 观察信号 | 服务端动作（都在配置层，孩子看不见） |
|---|---|
| 知识点停滞率 >15% 持续两周（§12） | 该知识点 R 权重临时降一档；必要时整组降一档（S3→S2），先把「又来了」的密度降下去 |
| 单组做题时长 P95 >8 分钟且集中在 R 段 | 该知识点暂停进 R 段 3 天（等同「连错 5 次」的处理），并检查题目难度是否异常 |
| 家长反馈「孩子问为什么老做这类题，我解释不清」≥3 次 | **由家长在 H5 上处理**：H5 的知识点详情里给一句可直接照着说的话术（家长说，不是电视说） |
| 停题按钮点击率上升 / 中途退出率上升 | 降低单组 R 题位（最多降到 1），把题位还给课程段 |

> **v1.3 曾留过一条退路**：「真到了那一步，在交卷结果页加一句中性文案（今天有 2 道是复习题）」。
> **v1.4 明确废弃这条**——中性文案同样会建立「做题 = 学习任务」的语义，且必然引出「哪些要复习」。
> 现在的边界是：**电视端呈现一律不做，任何情况都不作为缓解手段；缓解只能落在服务端参数与家长侧话术。**
> 如果哪天真的必须让孩子知道点什么，那是产品方向变更，要重开决策（改判断五），不是在实现里加一行字。

- 不做按 `wrong_count` 加权（终身计数会让老错题永久压制新错题，见 §6.7）；
- 不做孩子端的错题本（C13 仍按原规则：答案只给家长）；
- **不做电视端任何进度提示**（D5：对孩子透明。知识点名、次数、过关提示一概没有，见 §10）；
- **不做电视端任何薄弱知识点 / 强化练习相关的呈现**（v1.4：含中性文案「今天有 2 道是复习题」、
  图标、徽章、配色区分、排序暗示、无障碍朗读；连「隐晦版」也不做——隐性信号一样在分类，见 §10）；
- 不做「电视上一键标记坏题」（D5 之后改由家长在 H5 标，见 §11）；
- 不做多孩子共用一个电视的账号隔离（`owner_device` 已留扩展位，本期一个 device 一个孩子）；
- 不做数学以外的自动验算（语文/英语只靠模板答案集，没有「一定对」的推导，如实告知家长）；
- 不做试卷原题在电视上重做（§2 判断三）；
- 不做拍照给第三方 App / 不做分享。
