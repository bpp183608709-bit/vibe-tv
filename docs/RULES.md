# 数值规则：掌握度 → 判档 → 配额 → 抽样

> **这份文档是什么**：错题训练功能里**所有数字的唯一出处**。每个常数、每张对照表、每条边界条件，
> 以及「改了这个数会动到什么」。
> **不是什么**：不是需求文档，也不是决策记录。为什么要有这个功能、为什么不给孩子看进度、
> 为什么不用概率模型，在 `docs/WRONGBOOK.md`（§2 产品判断、§16 决策台账）。本文只管数字。
>
> **两处出现同一个数字时，以本文为准**；发现不一致请改成一致，并把过程记进 §8。

## 0. 怎么用这份文档

| 你要做的事 | 看哪节 |
|---|---|
| 查某个常数是多少、在哪个文件 | §1 参数总表 |
| 想知道「为什么这个知识点 72 分」 | §2 |
| 想知道「为什么这轮 5 题里只出了 1 道错题」 | §3 |
| 想知道「为什么出的是第 5 单元的题 / 什么时候开始出复习题」 | §3.0 |
| 想知道「三个薄弱点，为什么今天只出现一个」 | §4 |
| 想调参数 | §6 影响面 + §7 调参顺序，**不要跳过 §5 硬边界** |
| 想知道某个数是谁定的 | §8 |
| 想知道家长页上的分数、配比、流水是从哪来的 | §2.6 |

**一句话数据流**：

```
近 10 次作答 ──► 加权正确率（0–1）──► 档位 L0–L3（待测是第 5 种状态）
                                          │
                            ┌─────────────┴─────────────┐
                            ▼                           ▼
                  薄弱节点数 n + 深度 depth        档位签数 4/2/1/0
                            │                           │
                            ▼                           ▼
                    五题怎么分（S0–S3）          错题段里抽谁（加权）
```

三件事依次决定，**后面的不会反过来影响前面的**：窗口决定档位，档位决定配额和签数，配额和签数决定出什么题。

## 1. 参数总表

改任何一行，先看 §6 有没有连带影响。

### 1.1 掌握度（`server/app/mastery.py`）

分数不再是「累加薄弱分」，而是**最近 10 道题的加权正确率**。所以「越高越好」，0 分最差。

| 常数 | 值 | 含义 |
|---|---|---|
| `MASTERY_WINDOW` | **10** | 参与计算的最近答案数（滚动，不是累计） |
| `WEIGHT_X10` | 易 **10** / 中 **15** / 难 **20** | 每题权重 ×10，整数存库避免两次取整 |
| `PAPER_WEIGHT_X10` | **10** | 试卷错题无难度、无机判，按「易」计入 |
| `PAPER_PER_DAY` | **3** | 同一知识点每天最多几道试卷错题计入窗口 |
| `MIN_SAMPLE` | **3** | 少于这个数判「待测」，**不判薄弱、不进错题段** |
| `BAND_BASIC` | 400 | 千分制下界：正确率 < 0.4 → L0 |
| `BAND_SKILLED` | 600 | < 0.6 → L1 |
| `BAND_EXTENDED` | 800 | ≤ 0.8 → L2；**严格大于**才可能是 L3 |
| `LEVEL_WEIGHT_X10` | 40/20/10/0 | 档位签数 ×10（4.0/2.0/1.0/0；L3 按 0，永不进错题段） |
| `LEVEL_TARGET_QTY` | 10/7/5/3 | 该档应常备的可出题量，用于供给折扣与补题指标 |
| `LEVEL_DAILY_CAP` | 3/3/3/3 | 单知识点每天最多进错题段几道 |
| `PARENT_ADJUST` | **±10** | 家长手动微调的单次上限 |
| `PARENT_BIAS_MAX` | **±30** | 累计偏差上限；存 `topic_mastery.bias`，**不进窗口** |
| `WRONG_STREAK_PAUSE` | 5 | 连错几次触发暂停 |
| `PAUSE_MS` | 3 天 | 暂停时长 |
| `MAX_SCORE` / `MIN_SCORE` | 100 / 0 | `score` 的截断范围 |

## 2. 规则一：掌握度怎么算

### 2.1 一次作答怎么变成分数

```
窗口   = 该 (设备, 诊断节点) 最近 10 条 counted=1 的作答，按 seq 倒序
正确权重 = Σ 答对那几条的 weight_x10
权重合计 = Σ 全部 10 条的 weight_x10
正确率   = 正确权重 / 权重合计
level    = 正确率落档（§2.3）
score    = round((正确率 ×1000 + 10×bias) / 10)，截断到 0–100
```

一次作答只做三件事：**进窗口、重算、写一行流水**。没有累加，没有遗忘曲线，没有拟合。

| 事件 | 进窗口？ | 权重 | 说明 |
|---|---|---|---|
| 电视答对（易/中/难） | 是 | 10 / 15 / 20 | `counted=1` |
| 电视答错（易/中/难） | 是 | 10 / 15 / 20 | 权重照给，只是不算「对的」 |
| 电视答对 + 标记没学过 | **否** | — | 说真话不奖不罚，不写流水（B7） |
| 电视答错 + 标记没学过 | 是 | 10 / 15 / 20 | 标记不是免练卡，否则孩子会先点标记 |
| 试卷错题（当天前 3 道） | 是 | 10 | 无难度、无机判，按「易」 |
| 试卷错题（当天第 4 道起） | **否** | — | `counted=0`，一张卷子不能把窗口冲掉 |
| 退题（题目被判错） | **否** | — | 把原行标 `counted=0` 后重算 |
| 家长调整 | **否** | — | 只动 `bias`，不动窗口 |

> 窗口里第 11 条会把最旧的一条挤出去。所以「答对一次」不保证涨分——挤出去的那条如果也是对的，净变化是 0。

### 2.2 家长调整为什么单独存

`bias` 是 ±10/次、累计 ±30 的加数，**乘在窗口之外**。这样一次点击改的是显示与判档，改不了证据：
不管家长点多少下，窗口里那 10 条真实作答还是那 10 条，孩子的正确率随时可以在另一台设备上被重新算出来。

### 2.3 档位

| 档 | 加权正确率 | 签数 | 目标题量 | 每日上限 | 进错题段 |
|---|---|---|---|---|---|
| L0 未掌握 | < 0.4 | 4.0 | 10 | 3 | 是 |
| L1 基础 | 0.4 – 0.6 | 2.0 | 7 | 3 | 是 |
| L2 熟练 | 0.6 – 0.8 | 1.0 | 5 | 3 | 否 |
| L3 拓展 | > 0.8 **且难题至少答对 1 道** | 0 | 3 | 3 | 否 |
| 待测 | 作答 < 3 条 | — | — | — | 否 |

**签数按档给，不按分数连续折算**。两个直接结果，写在这里免得每次都要重新推：

- 0.41 和 0.59 签数相同（都是 2 张），差 0.18 而概率一样；
- 0.80 和 0.81 只差 1 个百分点，但 0.81 还要「难题答对过 1 道」才进 L3，否则仍按 L2 处理。

这是刻意的：连续映射没法向家长解释「为什么 62 分和 65 分概率不一样」，而档位边界本身的差别是真实的。

**L3 的门槛为什么多一道难题**：正确率 > 0.8 可以靠十道易题刷出来。没有难题证据就封顶 L2，
是为了让「拓展」这个词对应真实能力，而不是对应「题库刚好只有简单题」。

### 2.4 家长端的「再答对 N 次」

不是公式，是**模拟**：往窗口里连续塞 k 道「中」题（全对），看第 k 步能不能越过下一档的边界。

```
对 k = 1..11：模拟窗口 = k 条中题(全对) + 现有窗口，截到 10 条
              若正确率 > 下一档边界 → 返回 k
返回 11（表示「10 次以上」，H5 显示成「还要练一阵」）
```

几处必须记住的：

- **边界是严格大于**。五个里对三个是 0.6，正好卡在「熟练」的下界而不越界，所以从 0.6 到拓展要 **6 道**，不是 5 道；
- **旧答案会被挤出去**，挤出去的可能是错的也可能是对的。闭式解会高估，所以这里老老实实模拟 10 步；
- **待测节点返回 0**，「再答对 0 次」没有意义，H5 改说「再答 N 道就能看出来」；
- 该值**只在 H5 出现**，不落库、不写进任何电视响应。


### 2.5 暂停

同一知识点连续答错 5 次 → 该知识点**暂停 3 天**，期间不进错题段。

- 暂停只影响「进不进错题段」，不影响课内出题；
- 触发后连错计数**立刻归零**。不归零的话第 6 次错会立刻再触发一次暂停，等于永久暂停；
- 已在暂停期内再次连错 5 次**不会延长**暂停（`mastery.still_paused` 判断）。

**暂停与分数无关**。它是「别再拿这一类题去问他」的短期开关，不改窗口、不改正确率；
暂停结束时分数还在原处，因为证据没有变。

### 2.6 这些数字的第二个读者：家长页

掌握度有两个出口：出题逻辑（§3、§4）和 H5 的几个页面。列清楚，免得改了一边忘了另一边：

| 家长页上的东西 | 从哪来 | 会不会反过来影响出题 |
|---|---|---|
| 分数 / 档位 / 签数 / 目标题量 | `topic_mastery.score` / `level`，档位由 `level_of(acc_x1000, hard_right)` 现算 | 不会。页面只读 |
| 加权正确率 / 样本数 / 难题答对数 | `acc_x1000` / `sample_count` / `hard_right` | 不会 |
| 「再答对 N 次」 | `need_right(acc, sample, hard_right, bias, window)`，§2.4 | 不会。不落库 |
| 「再答 N 道就能看出来」（待测） | `need_sample(sample_count)` | 不会。不落库 |
| 今日配比 C/P/R | `daily_state.mix_c`、`mix_r`，**读快照** | 会——但读的是已冻结的值，页面打开几次都不改它 |
| 加减分流水 | `mastery_event` 逐行，`delta` 是 **`score` 的生效差值** | 不会。回放求和必须等于当前分数，验收有专门断言 |
| 「今天已出 2 题（上限 3）」 | `quiz_session.review_question_ids` 反查（`picker.review_used_today`） | 不会。和出题次数用的是同一个计数 |
| 档位词（未掌握 / 基础 / 熟练 / 拓展 / 待测） | 纯文案，`h5.LEVEL_WORDS` 与前端 `TEXTS.*.wrong.word0..3` | 不会。改词不动任何数字 |

三句必须记住的话：

- **页面绝不调用 `mix.snapshot`**。它会写当日快照，等于家长点一下 tab 就替孩子把这一天的配比定了。
- **档位词不是档位**。改 `LEVEL_WORDS` 只是改称呼；改 `BAND_*` 才是改档位，那时 §2.3、§2.4 的示例、
  `mix.WEAK_MAX_LEVEL` 和验收的档位边界用例要一起动。
- **`delta` 的符号反了**。旧模型里分数越高越薄弱，答对是负的；现在 `score` 是掌握度，答对是正的、
  答错是负的。凡是「看到负号就以为是进步」的旧代码或旧文案，都要重新读一遍。

## 3. 规则二：五题怎么分三段

每轮固定 5 道题，从三个来源取：**当前单元（C）**、**已学的其他单元（P）**、**错题段（R）**。

### 3.0 先解决「当前单元」从哪来

这个问题以前不存在，因为那个数从来不动：`curriculum_progress.current_unit_ordinal` 在设备首次出题时被写成 1，之后再没有任何代码改它。孩子在学到第 5 单元，系统仍在出第 1 单元的题。

现在有两个来源，后者压过前者：

| 来源 | 怎么算 | 什么时候用 |
|---|---|---|
| **日历** | `week = (今天 − 开学日) // 7 + 1`，取 `week_start ≤ week` 的最大单元 | 家长设过一次开学日期之后的默认方式 |
| **家长** | 直接指定第 N 单元 | 日历算错时的手动修正：调课、放假、孩子超前或落后 |

```
week_in_term = max(1, (today - start_date).days // 7 + 1)
current      = max{ ordinal : unit.week_start <= week_in_term }   （没有任何单元满足时取 1）
```

三条规则：

1. **`unit.week_start` 为空的单元，日历永远不会把它算成当前单元**（只能靠家长指定）。
2. **开学日之前一律算第 1 周**，不是第 0 周：家长把下周设成开学第一周，不该看到进度清零。
3. **家长的值一直有效，直到家长把它交还给日历**。理由是「有人特意填的数不该被算术覆盖」；H5 上对应一个「恢复自动」按钮，点一下把所有册的覆盖一起释放。

**学期学完是一种状态，不是一个错误。** 当 `current` 到达该册最后一个单元（`current >= last`），`reviewing` 为真，`current` 就不再对某册表示「正在教这个单元」了。注意 `last` 取 `max(ordinal)` 而不是单元个数——语文的编号是 1、2、7、8。

每册独立判定：数学可能已经复习、英语还在授新课，两者同时成立是正常的。

### 3.1 两个维度各判一档

| 维度 | 取值 → 档位 |
|---|---|
| 数量 `n` | 0 → S0｜1–2 → S1｜3–4 → S2｜5+ → S3 |
| 深度 `Lmax` | 无 → S0｜基础(1) → S1｜未掌握(3) → S3 |

`n` **只数真能出题的薄弱点**：档位 ≤ 1（`WEAK_MAX_LEVEL`）、样本 ≥ 3（`MIN_SAMPLE`）、
当前难度下近 7 天还有没出过的题、不在暂停期。把一个出不了题的算进去，等于承诺一个填不上的坑。

**深度不是档位**。档位数的是掌握（0 未掌握 … 3 拓展），深度数的是薄弱（未掌握 = 3，基础 = 1，
熟练及以上根本没有深度）。只有薄弱节点才有深度可言——所以深度只有 1 和 3 两个取值，中间没有 2。

### 3.2 判档矩阵（两个维度取较重）

| n \ Lmax | 无 | 基础(1) | 未掌握(3) |
|---|---|---|---|
| **0** | S0 | — | — |
| **1–2** | — | S1 | **S3** |
| **3–4** | — | S2 | **S3** |
| **5+** | — | S3 | S3 |

「—」是不可能出现的组合：没有薄弱点时深度必为空，有薄弱点时深度至少是 1。
`state_for` 在 `n = 0` 时直接返回 S0，不吃矛盾输入（自检里有断言）。两点值得记住：

- **一个知识点掉到未掌握，不论总数多少，直接 S3**（深度那一票是 3，压过任何数量）；
- **4 个基础节点（n=4）是 S2，3 个基础里含 1 个未掌握也是 S3 起步**——数量和深度各自封顶，取高的那个。


### 3.3 配额

| 状态 | C 当前单元 | P 前单元 | R 错题段 |
|---|---|---|---|
| S0 | 5 | 0 | 0 |
| S1 | 4 | 0 | 1 |
| S2 | 3 | 0 | 2 |
| S3 | 2 | 1 | 2 |

**只有 C 和 R 两个旋钮，P 是余量**（P = 5 − C − R）。一个组只有 5 个位置，三个数不可能各自独立。

**但三段的含义随学期阶段变**，这一层以前是隐含的：

| 段 | 学习期（`reviewing = false`） | 复习期（`reviewing = true`） |
|---|---|---|
| **C** | 当前单元 | 本学期全部已学单元（上限改成 `5 − R`） |
| **P** | 已学的其他单元，**全部**；不是「前 2 个」 | 无（已并入 C） |
| **R** | 薄弱知识点 | 同左 |
| 兜底 | 未学单元——只在已学部分凑不满 5 题时才动它 | 同左 |

两条改动的原因：

1. **P 段放开到全学期**，因为固定两个单元的窗口在学期末等于「只复习最近两周」。9 月学的分数乘法在 12 月从不出现在题里，却仍算「学过」。放开后按**覆盖优先**排序（没做过 → 最久没做 → 错误次数），与 R 段「错得多的优先」正好分工：P 管广度，R 管巩固。
2. **复习期 C 段改成全学期**，因为「当前单元」这时指的是最后一单元，把 5 题全压在那里是最不像复习的做法。上限改成 `5 − R` 而不是继续用 `c`：若仍用 `c`，超出的部分会经由「供给不足」那条兜底路径补回来——同样的结果，但那是事故，不是规则。

**学习期的 C 段仍按错误次数排序**（当前这周课最需要被盯着），**复习期改成覆盖优先**。

### 3.4 三条硬边界

| 边界 | 为什么 |
|---|---|
| **R ≤ 2** | 到 3 时科目轮转会把某一科的课内题挤掉，整组变成「又是那几个知识点」 |
| **C ≥ 2** | 这终究是一场考试，不是补习班 |
| **一组内同一知识点 ≤ 2 道** | 三个来源合计；再多就是同一道题换皮 |

### 3.5 快照：一天只算一次

当日第一组题时算好，写进 `daily_state`（`mix_state` / `mix_c` / `mix_r` / `mix_n` / `mix_deepest` / `mix_note`），
当天所有组照用。否则孩子连错两道，R 立刻从 0 变 1，做对一道又变回去——他会觉得系统在抽风。

`mix_deepest` 也一起冻结：深度是从档位算出来的，档位会随作答变，冻结的必须是**当天判档时看到的那一个深度**。

**一个例外**：当日有知识点**新变薄弱**（`topic_mastery.weak_since` 落在当天），
即使快照是 R = 0，也临时给 1 位（C 4 / R 1），并写进快照。
否则「家长上午拍照录入、下午那组就该出现」要等到明天才成立。

判据必须是 `weak_since` 而不是 `last_event_at`：后者答对一次也会刷新，
按它判会让「今天答对过的薄弱节点」误占新来的那一位。


### 3.6 供给不足时，坑要还回去

按顺序退让，任何情况下都**不重复出已出过的题来凑数**：

1. R 段抽不满 → 空位退回课内；
2. C 段达到上限 → 多出来的给已学的其他单元；
3. 还需要 → 把 C 上限放开到 5 再补；
4. 仍不足 5 题但 ≥ 3 题 → 就发这个数（`MIN_GROUP_SIZE`）；
5. 少于 3 题或不足两科 → 报错，不发残缺组。

## 4. 规则三：错题段里抽谁

### 4.1 先过资格

进不了池子的四种情况（任一命中即排除）：

- 样本 < 3（待测：还不够判）；
- 档位 ≥ 2（熟练 / 拓展，`mix.WEAK_MAX_LEVEL = 1`）；
- 当前处于暂停期；
- 当前难度下、近 7 天没有可出的题。

「待测」被排除在这条之外，是这次重构最容易被误解的一处：**没测过不等于弱**。
如果待测能进错题段，题库一大半节点会同时变成「薄弱」，配额直接顶到 S3，而那批节点里
多数其实只是还没被问到。

### 4.2 权重 = 签数 × 供给折扣

```
权重 W = 档位签数 × min(1, 池里还能出的题数 / 该档目标题量)
```

| 情形 | 签数 | 池里剩 | 折扣 | 实际 W |
|---|---|---|---|---|
| 未掌握，目标 10，剩 10 | 4 | 10 | 1.00 | **4.0** |
| 未掌握，目标 10，剩 4 | 4 | 4 | 0.40 | **1.6** |
| 基础，目标 7，剩 7 | 2 | 7 | 1.00 | **2.0** |
| 基础，目标 7，剩 1 | 2 | 1 | 0.14 | **0.29** |

**折扣的意义**：题库只剩 1 道的知识点，按原权重会天天被抽中，每次都是同一道题——孩子第二天就记住答案了。
宁可这次几乎不问，也不重复问。**补题的优先级因此高于调权重**（见 §7）。

### 4.3 抽签时权重还要按题均分

W 属于**知识点**，不属于每道题。抽签时每道题携带 `W / 该知识点在池中的题数`，
池子每抽走一道就重算分母。

不做这一步的话，一个题库里恰好有 10 道题的知识点会以 10 份权重压过只有 3 道题的更弱知识点——
决定频率的变成「题库恰好多大」，不是「孩子多弱」。实测差异：400 次抽样里未掌握档曾占到 81%，
修正后回到 67%（4:2 ≈ 0.67）。

### 4.4 抽签过程

- 无放回，一次抽一道（不是先洗权重再排序——同知识点上限和日上限会改变可选集合，洗牌会悄悄忽略它们）；
- 随机源是 `random.Random(now_ms)`，同一毫秒完全可复现；
- 抽满 R 个位或池子抽干为止。

### 4.5 三条限额（会挡住上面算出的概率）

| 限额 | 值 | 统计口径 |
|---|---|---|
| 一组内同一知识点 | ≤ 2 道 | 三个来源合计（`per_topic`） |
| 单知识点每天进错题段 | ≤ 3 道 | **按「次」不按「题」**，且算**已发出**的会话 |
| 同一道题重复出示 | 7 天内不再出 | `question` 的最近出现时间 |

**「按次不按题」这条必须照做**：用 `WHERE id IN (…)` 统计会把重复抽中的同一道题合并成一条，
于是「今天出了 4 次」被数成「3 道不同的题」，上限形同虚设。
**「已发出的会话」也要算**：否则反复开局就能刷到简单题。

### 4.6 孩子看到的顺序

抽完之后整组打乱（`shuffle`），错题不排在固定位置，也不在最后——否则孩子会记住「第三题总是英语」。

## 5. 不可违反的数值约束

改参数前逐条确认，这些不是风格问题，是正确性问题：

1. **没有任何掌握度记录、进度为第 1 单元时，出题结果必须与引入本功能前逐题一致**。验收里有一份冻结的旧实现做逐 `question_id` 比对。这条只管这一个场景：一旦存在薄弱点、或题被做过、或进度推到第 3 单元，「已学」不再等于「当前单元」，比对就没有意义了——不要把它当成「任何改动都违法」的挡箭牌。
2. **`mastery_event.delta` 记 `score` 的实际生效差值**，不是名义权重，也不是正确率变化。clamp 会吃掉差额，
   照抄名义值会让流水永远加不回 `score`。验收有一条「重放流水 == 存储分数」。
3. **`mastery_event.counted` 是窗口的唯一入口**。窗口查询必须带 `counted = 1`；
   任何时候要「抹掉一条证据」，做法是把行改成 `counted = 0` 再重算，**不是**反推一个反向 `delta`——
   在非线性的正确率模型下反推会翻符号（退题一次反而让分数下降）。
4. **窗口排序只认 `seq`，不认 `created_at`**。一次提交会写 5 行、时间戳完全相同，
   按时间排会让窗口顺序不确定，同一份数据算出两个正确率。
5. **`R_CAP ≤ 2` 且 `C ≥ 2`**，`QUOTA` 每行必须满足 C + P + R = 5。
6. **响应体字段集合完全冻结**：`/v1/quiz/next` 与 `/grade` 不许多出任何进度 / 知识点 / 段落字段。
   白名单写在 `server/tools/acceptance.py`，文本禁用词由 `server/tools/check_tv_silence.py` 全目录扫描。
7. **同一时刻可复现**：任何新的随机行为都必须挂在 `now_ms` 上，不许用 `random` 全局状态。
8. **`PER_TOPIC` 同时约束三个来源**。只约束错题段的话，课内段可以合法地把同一个知识点出 3 道。
9. **`schema.sql` 与 `schema.sqlite.sql` 必须逐列对齐**（`check_schema_parity.py`）。加列时两处一起加，
   否则验收跑在 SQLite 上、线上跑在 MySQL 上，等于两套表。

| `PAPER_PER_DAY`（3） | 拍照录入变成无效操作 | 一张卷子把 10 条真实作答全挤出去 | 验收「第四道当天不计入」 |

| `PREV_WINDOW` | **已废弃**（§3.3）：P 段现在是全学期，没有窗口可调。改回窗口等于把孩子 9 月学的又排除在外 | | 若真要恢复窗口，`picker._tier`、§3.3、验收「9 月单元算前单元」用例一起改 |
| `term_anchor.start_date` | 换早 → 进度超前，会出到还没教的单元 | 换晚 → 进度滞后，复习的都是旧单元 | 验收「第 11 周在第 5 单元」；H5 设置页 |
| `reviewing` 判定（`current >= last`） | 提前判复习 → 新课还没上完就不再出当前单元 | 推迟 → 学期末还在死磕最后一个单元 | 验收「第 21 周已复习」；H5 状态文案 |
| `R_CAP`（2） | R 更保守 | **>2 会挤掉课内题位** | §3.4、验收占比 |
| `NEWCOMER_SLOTS`（1） | 今日录入当天看不到 | 破坏当日快照的意义 | 验收「今日新增占 1 位」 |
| `PER_TOPIC`（2） | 一组只有一个知识点 | 同一知识点刷屏 | 验收、`picker` 自检 |
| `GROUP_SIZE`（5） | 配比表全部重算 | 同上 | `QUOTA`、`MIN_GROUP_SIZE`、所有题数断言 |

**调参的乘法效应**：档位边界一动，配额表、签数、日上限、`need_right` 会同时变。
所以边界只在有明确理由时动，日常调优优先动签数和日上限。

**`target_difficulty` 与「还差一道难题」**：`limits.target_difficulty` 现在会返回 3（难题），
触发条件是「有节点的正确率已过 0.8 但还没答对过难题」——那正是 L2 卡在 L3 门口的唯一原因。
把 `BAND_EXTENDED` 调低会同时改变这个条件的命中率，验收里「L3 需要难题」的用例会先红。

## 7. 调参的推荐顺序

按「改动成本 / 可逆性」排，前面的能解决就不要动后面的：

1. **先看题量够不够**（补题、扩模板）。供给折扣说明很多「概率不对」其实是题不够，不是权重不对；
2. 调 `LEVEL_DAILY_CAP`：只说「一天最多出几道」，不改变长期比例，最容易回滚；
3. 调 `LEVEL_WEIGHT_X10`：改变薄弱点之间的相对频率，不影响配额；
4. 调 `QUOTA`：改变三段比例，影响最直观，也最容易被孩子察觉；
5. 调 `BAND_BASIC / SKILLED / EXTENDED`：最后手段，一次改动会重算上面全部。

**每次只动一个参数，并保证能回答两个问题**：改之前预期哪个指标动、动多少；改之后实测是多少。
观测指标见 `docs/WRONGBOOK.md` §12（知识点停滞率 ≤15%、家长查看率 ≥50%）。

## 9. 已知取舍（不是缺陷，是选过的）

1. **四档的每日上限都是 3**。没有按档位区分强度，因为孩子感知不到区别，却会让「今天还能做几道」变得不可预测。
2. **签数按档给，四档分别是 4/2/1/0**，中间没有过渡。0.41 和 0.59 的知识点概率相同，0.59 和 0.61 会跳一个档。
3. **供给折扣会让最弱的知识点几乎不出现**（只剩 1 道题时权重 0.29）。这是有意的：重复同一道题的伤害大于少练。
4. **`n` 只数能出题的**，所以「家长看到 5 个薄弱点、系统只认 3 个」是正常现象。H5 需要标明哪些当前练不了。
5. **一组里同一知识点最多 2 道**（三个来源合计）。这限制了单轮强度，强度只能靠「次数」累积，不能靠「一道接一道」。
6. **未学单元的题仍是兜底**，不会彻底禁掉。学期初题库没铺满时，宁可出一道稍超前的题，也不要让孩子点「去做题」却收到一个错误。代价是那道题可能被算进掌握度——好在它答错只是提前暴露一个问题，答对则说明这个节点确实会了。
7. **P 段按覆盖优先，不按错误次数**。这意味着一个老错的函数题不会因为「更该练」而反复出现在课内段；它该出现的地方是 R 段，那里权重 4/2 才是为它准备的。
8. **进度只会前进，不会自动后退**。家长把某个孩子调回低单元重学，需要手动指定；日历不会因为时间到了就自动回退。
9. **待测节点不判、不练、不显示分数**。代价是新建的题库里大多数节点会长时间停在「待测」——这是刻意的：用 1 道题的样本去说「他没掌握」，比不显示更糟。
